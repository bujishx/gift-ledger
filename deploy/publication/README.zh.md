# 往来有礼

在家中局域网或 VPN 上为自己和家人部署礼金账本。首版支持 Linux/amd64 的 Ubuntu 与群晖 Container Manager。[English](README.en.md)

## 安装

先在准备建站的服务器核对端口和网段。指南分别给出 Ubuntu、群晖的只读命令，以及“端口被占用”和“分不到网络”的处理步骤。[安装前检查端口与网络](https://github.com/bujishx/gift-ledger/releases/latest/download/Install-network.zh.txt)

从同一发行版本下载一个 [docker-compose.yml](https://github.com/bujishx/gift-ledger/releases/latest/download/docker-compose.yml)。在专用空目录中保存它，用文本编辑器将顶部的局域网 IP 和端口改为本站的地址，例如 `192.168.1.20` 和 `8443`。在线安装时服务器需要能下载发行版指定的镜像。使用离线候选包时，先按包内说明核对并导入配套镜像，再使用包内同一份 YAML。

- **Ubuntu** 在 YAML 顶部的 `name:` 填写项目名。已安装 Docker Engine 与 Compose 插件后，在 YAML 目录执行 `docker compose up -d`。
- **群晖** 在 File Station 建一个专用空文件夹，例如 `/volume1/docker/gift-ledger-family`，把 YAML 放进去。在 Container Manager → 项目 → 新增中填写项目名，选择该文件夹并使用已有 YAML。文件夹名可以自取。为方便以后在终端操作，建议 YAML 顶部的 `name:` 和群晖项目名填成一样。

同一台主机再建独立站时，请另取项目名、使用另一个空闲 HTTPS 端口，并选择另一个专用空文件夹。两个站可以使用同一个局域网 IP。默认数据和备份都在各自的文件夹下。

安装完成后，在站点文件夹的 `data/` 中，找到以“项目名-实例前8位-”开头的“网站地址.txt”和“本站维护说明.txt”。例如项目 family 的根证书名可能是 `family-1234abcd-本站根证书.cer`。后者列出本站网址、项目名、实例以及可直接复制的维护命令。网页维护首次启用时，在本站服务器管理员终端执行“启用本站网页维护（每站一次）”中的整段命令。看到“本站维护服务已就绪”后，Ubuntu 已设置开机启动。群晖还需按该节保存本站的开机触发任务。

把同目录中带本站前缀的“本站根证书.cer” 送到手机或 Mac，按“核对公开根证书”比对 SHA-256 后再信任。DSM 的 `prepare` 日志页为空时，说明中的命令可从 SSH 读取日志及服务器文件的指纹。同名下载可能带有 `(1)` 等后缀，按指纹选择。手机连接局域网或 VPN，打开网址，注册、完成本人建档、记一笔。

在 Mac 上将指纹已核对的根证书导入“登录”钥匙串。打开“钥匙串访问”，在“证书”列表中双击本站的 `GiftLedger Site CA` 证书，展开“信任”，将“安全套接字层（SSL）”设为“始终信任”。关闭详情窗口，按系统提示确认，再打开本站网址。[Apple 钥匙串访问指南](https://support.apple.com/zh-cn/guide/keychain-access/kyca11871/mac)

重启服务器后，用原账号登录并核对这笔账。忘记账号或密码时联系本站站主。已安装的 YAML 固定镜像摘要，站主自行选择升级时间。

## 可选的外网记账地址

只用内网时，保留 YAML 顶部 `x-reverse-proxy-origin` 的空值。需要外网记账时，填写浏览器实际使用的 HTTPS 域名和端口，例如 `"${GIFTLEDGER_REVERSE_PROXY_ORIGIN:-https://ledger.example.org:51888}"`。同时保留原内网 IP 和端口。项目仍只发布原来的内网端口。

在 DSM 的 HTTPS 反向代理中，为外部域名选择匹配的证书，将请求转发到本站原内网 HTTPS 地址。让这条公网规则将发往上游的 `Host` 固定为外部域名及端口，例如 `ledger.example.org:51888`（HTTPS 默认 443 可省略）。保留浏览器原始的 `Origin`。路由器只向公网开放反向代理入口，内网网站端口仅供局域网访问。如果转发时把 Host 改成内网 IP，带有常见转发标头的请求会被拒绝。

公网登录每个已核实的来源 IP 每秒可请求 1 次，整站合计每秒 2 次，两项均允许额外突发 2 次。内外网业务登录共用 1 个密码校验名额。额度或名额用尽时提示稍后再试，不计为密码输错。查账和记账不占登录额度。

要让同一反向代理后的访客按各自 IP 限速，在公网规则中将上游请求头 `X-Real-IP` **覆盖为** `$remote_addr`，并按部署方式核实代理身份。

- **同机群晖 DSM 或共享 Docker 网关**。在站主自己的终端用 `openssl rand -hex 32` 生成密钥。在 YAML 所在目录的私有 `.env` 文件中添加 `GIFTLEDGER_REVERSE_PROXY_KEY=生成的64位小写十六进制值`。打开 DSM「控制面板 → 登录门户 → 高级 → 反向代理服务器」，编辑本站公网规则，在自定义请求头中设置 `X-Real-IP` 为 `$remote_addr`，并将 `X-GiftLedger-Proxy-Key` 覆盖为同一个密钥。保存规则并重新构建原项目。请妥善保管 `.env`，对外分享 YAML 时保留公版的空默认值。
- **有固定专用 IPv4 的独立代理**。在同目录 `.env` 中设置 `GIFTLEDGER_REVERSE_PROXY_IP=代理的IPv4地址`，填写网站容器实际看到且仅由这台代理使用的 TCP 来源地址。保留代理对 `X-Real-IP` 的覆盖设置。共享网关请使用上面的密钥方式。如果同时设置 IP 和密钥，网站会核对两者。

旧站升级可以继续使用已有公网域名。两项都留空时，公网登录保留整站限速与后台校验名额。设置了可信代理后，如果公网登录提示“登录来源未能核实”，请核对代理的出站 IP 或密钥，并确认规则覆盖了有效的访客 IP；该请求会在密码校验前被拒绝。共用同一个公网出口 IP 的访客共享该来源额度。

在原项目保存 YAML 后重新构建，再从外网打开域名并登录。域名和内网 IP 分别登录，共用同一账本。请同时确认外网域名的 `/maintenance` 被拒绝，内网 IP 的维护页仍能打开。整站维护、整库备份、个人备份与恢复都在内网操作。取消外网记账时，将第 4 项 `x-reverse-proxy-origin` 设回空值并重新应用项目配置。已有站升级请先做一份核验成功的离机备份。[站主升级](docs/站主升级.md)

## 在维护页找到相应操作

在内网记账登录页“立即注册”下方，或在记账页的“关于”中，点**站点维护**。要回到账本，可在维护登录页、已登录的维护页（电脑和平板在侧栏左下角，手机在页底）或“关于本站”中点**在新标签打开记账网站**。这些入口都在新标签页打开，原标签页会保留。记账账号和站主身份各自登录。

站主登录后，打开**站点总览**查看网站和数据库、最近备份解密核验、证书到期日及备份目录所在卷的可用空间。**注册用户**显示业务登录名、本人姓名、联系人、事件、记账数量和最近登录。启用采集前的登录显示“尚无记录”。核实本人后，可在此查找登录名或重置业务密码。

在内网维护页的**注册用户**中，可以单独设置内网注册，或将公网注册设为“关闭”“仅限邀请”“开放注册”。新站内网开放，公网默认仅限邀请。邀请码一人一码，48 小时有效，可提前作废，注册成功才消耗。已有账号仍可登录。停用账号会立即阻止该账号继续访问，资料保留，可在“已停用”中重新启用。只有未建本人档案且无业务资料的账号可以删除。公网“关于本站”显示产品名称、网站版本及公版 GitHub 项目链接。公网“我的”页保留灰显的“备份恢复”菜单，并标注“仅限内网”。

公版 YAML 按 SHA-256 摘要指定五个镜像。启用或更新本站宿主维护服务后，它会核对本地镜像并添加对应的发行版本标签，站主可在群晖 Container Manager 的“映像”中查看。

打开**维护操作**登记或管理钥匙、手动备份、下载已核验的备份，以及把旧备份恢复到独立空站。**关于本站**显示版本、构建提交和目标实例号，最近一次整站恢复有核验记录时会显示其时间。复用同一网址时，可将这里的实例号与目标站维护说明核对。电脑和平板从侧栏进入，手机从底栏进入。

## 在浏览器备份与恢复

1. **登录本站维护页。** 用 Windows、Mac 或 Ubuntu 桌面的浏览器打开维护说明中列出的地址。它与记账网站使用相同的 IP 和端口，网址末尾是 `/maintenance`。在服务器管理员终端运行“站主维护登录码”中的命令，核对项目和网址，输入短时码。也可以在页面上设置站主密码，忘记时用新的短时码重设。
2. **登记本站日常备份钥匙。** 从零建账的站和用旧备份恢复的新站都可以选“上传旧钥匙登记”或“生成新钥匙登记”。选择旧钥匙时，打开电脑或 U 盘中保存的原文件，例如 `identity.txt` 或 `.agekey`。在浏览器生成新钥匙时，文件名为 `key-<文件 SHA-256 的前 32 位>.agekey`。先下载保存，再选中刚保存的文件。点“确认登记到本站”，等到出现“本站备份钥匙登记通过”。重新打开“本站备份钥匙”即可查看登记时的文件名和公钥，也可点“核对本地钥匙”在本机核对文件。卡片单独显示本站首次通过解密核验的备份。
3. **备份并核账。** 点“开始备份”。按钮显示“等待执行”或“备份中”时，任务已经提交。网站会短暂停用，稍后回到同一维护页点“查看备份结果”。核验成功后点“下载已核验的备份 ZIP”，与对应的原钥匙分开保存。用原账号打开记账页，核对最后一笔和收支合计。
4. **把旧备份恢复到独立空站。** 建立另一个项目，使用另一端口和空文件夹。保持目标站尚未注册账号，从**目标站**的维护页选择旧站备份和制作备份时的原钥匙。点“上传并预检”，核对源站、笔数、目标网址和项目，输入“恢复”，再点“确认恢复到本站”。用原账号登录恢复后的站点核账。接下来在用旧备份恢复的新站首次备份时，可选“上传旧钥匙登记”或“生成新钥匙登记”。[完整恢复步骤](docs/从备份恢复.md)

**补领和更换钥匙。** 在本站维护页的“管理已登记的备份钥匙”卡片中选择补领或更换。群晖和 Ubuntu 都需服务器管理员核对项目、网址和实例，输入本页接收码，把加密回执交回同一页。补领后，重新打开保存的钥匙，实际解开指定备份。点“更换今后备份的钥匙”可选“使用已有钥匙”或“生成新钥匙”。已有钥匙可从电脑或 U 盘选取；若是当前钥匙，页面会提示无需更换。选用另一把已有钥匙时，打开管理员回执，把页面生成的加密钥匙包交给等待中的管理员终端。生成新钥匙时先下载，再从保存位置选回。按页面给出的确认码授权服务器制作首份备份，通过实际解密核验后才切换。历史备份继续用制作时对应的钥匙恢复。

**网页暂时打不开时**，打开服务器 `data/` 中带本站前缀的维护说明，运行“网页暂时打不开时查看本站维护任务”中的命令。按原任务编号核对进度和救援说明。需要使用终端时，本站维护说明也提供手动备份命令和同版桌面工具的登记、恢复命令。[Mac 站主工具](https://github.com/bujishx/gift-ledger/releases/latest/download/mac-site-tools.zip) · [Windows 站主工具](https://github.com/bujishx/gift-ledger/releases/latest/download/windows-site-tools.zip)

群晖手动备份支持 Container Manager 24.0.2-1543 和 24.0.2-1606，任务启动时会校验套件文件。若显示 `CM_vendor_file_set_unreviewed`，此项检查会在停站前结束任务。请反馈套件中心显示的 Container Manager 版本号和任务计划中的运行结果。

## 证书到期与续签

新建站点或续签时，网站 HTTPS 证书有效 **365 天**。旧证书继续使用到当前到期日，续签后采用新期限。打开 `data/` 中带本站前缀的维护说明，运行“查看证书有效期”可看到网站证书和根证书各自的到期时间。

**Ubuntu** 在启用本站网页维护时安装并启用证书定时任务，每天按服务器当地时间 03:15 检查。可按维护说明中的“Ubuntu 自动续签网站证书”查看下次检查时间和上次结果。

**群晖只需为每个站设置一次排程。** 按维护说明中的“群晖自动续签网站证书”新建并启用每天运行的任务，例如每天凌晨 03:15。网站证书还剩 30 天或更短时才续签，换证时网页会短暂停用。若已设置 DSM 邮件通知，可在任务中选择仅在脚本异常终止时发送运行详情。需要在群晖上立即换证时，可运行“续签本站 HTTPS 证书”，再从原网址核对新到期时间。[群晖任务计划说明](https://kb.synology.com/zh-cn/DSM/help/DSM/AdminCenter/system_taskscheduler?version=7)

本版新建站点的根证书到公元 **9999 年 12 月 31 日 23:59:59 UTC**。已有站点保留原根证书及原到期时间。换发网站证书会沿用本站根证书，已信任它的设备可继续访问原网址。若工具提示现有根证书有效期不足以签发完整的 365 天网站证书，请在当前网站证书到期前备份并恢复到独立新站，核账并信任新站根证书后切换。早期版本请先按指南升级。[升级与回退](docs/站主升级.md)

站点文件夹的 `data/站主指南/` 中有离线版《安装前检查端口与网络》和带本站前缀的《如何彻底删除本站》。决定退站时先把删除指南保存到站点外，按实际项目、实例和路径核对清单，再选择自己的平台操作。

站主可查阅[账号找回](docs/站主找回账号.md)和[升级与回退](docs/站主升级.md)。
