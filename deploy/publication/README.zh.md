# 往来有礼

在家中局域网或 VPN 上为自己和家人部署礼金账本。首版支持 Linux/amd64 的 Ubuntu 与群晖 Container Manager。[English](README.en.md)

安装可选 Ubuntu 或群晖。下文的备份、恢复和证书维护步骤已在群晖 DSM 上实测。Ubuntu 的新版维护指引将在实机验证后补充。

## 安装

从同一发行版本下载一个 [docker-compose.yml](https://github.com/{GITHUB_REPOSITORY}/releases/latest/download/docker-compose.yml)。在专用空目录中保存它，用文本编辑器将顶部的局域网 IP 和端口改为本站的地址，例如 `192.168.1.20` 和 `8443`。确保端口空闲，首次安装时服务器可访问 Docker Hub。

- **Ubuntu** 已安装 Docker Engine 与 Compose 插件后，在 YAML 目录执行 `docker compose up -d`。
- **群晖** 将 YAML 放在例如 `/volume1/docker/gift-ledger` 的文件夹。打开 Container Manager → 项目 → 新增，项目名填 `gift-ledger`，选该文件夹并使用已有 YAML。

安装完成后，在站点文件夹打开 `data/网站地址.txt` 和 `data/本站维护说明.txt`。后者列出本站网址、项目名、实例以及可直接复制的维护命令。若尚未显示宿主机上的项目文件夹，按说明在服务器运行“查看本站目录”一整段，再打开文件即可。

把同目录的 `本站根证书.cer` 送到手机或 Mac，按“核对公开根证书”比对 SHA-256 后再信任。DSM 的 `prepare` 日志页为空时，说明中的命令可从 SSH 读取日志及服务器文件的指纹。同名下载可能带有 `(1)` 等后缀，按指纹选择。手机连接局域网或 VPN，打开网址，注册、完成本人建档、记一笔。

在 Mac 上将指纹已核对的根证书导入“登录”钥匙串。打开“钥匙串访问”，在“证书”列表中双击本站的 `GiftLedger Site CA` 证书，展开“信任”，将“安全套接字层（SSL）”设为“始终信任”。关闭详情窗口，按系统提示确认，再打开本站网址。[Apple 钥匙串访问指南](https://support.apple.com/zh-cn/guide/keychain-access/kyca11871/mac)

重启服务器后，用原账号登录并核对这笔账。忘记账号或密码时联系本站站主。已安装的 YAML 固定镜像摘要，站主自行选择升级时间。

## 备份

1. **登记钥匙（每站首次备份前做一次）。** 从零建账的新站和用旧备份恢复的新站，都按本站 `data/本站维护说明.txt` 的“第一次备份前登记钥匙”操作。下载同版本的 [Windows 站主工具](https://github.com/{GITHUB_REPOSITORY}/releases/latest/download/windows-site-tools.zip) 或 [Mac 站主工具](https://github.com/{GITHUB_REPOSITORY}/releases/latest/download/mac-site-tools.zip)。Windows 打开 `GiftLedger.cmd` 选择登记，Mac 复制并运行说明里的登记命令。工具会同时显示两项，由站主选择。

   - **登记旧钥匙**。选择自己已保管的备份钥匙 `.agekey` 原文件。
   - **生成新钥匙并登记**。选择新钥匙的保存位置，工具会把它登记到这个站。

   看到“本站备份钥匙登记通过”后，单独保管原文件。若已生成钥匙但登记中断，再次打开登记工具，选择“登记旧钥匙”，选取刚才生成的文件。

2. **在群晖运行手动备份。** 复制本站维护说明中“手动备份”的完整命令。在 DSM 的“控制面板 → 任务计划”建立用户自定义脚本，用户选 root，关闭自动排程，将命令粘贴到脚本栏，保存并点“运行”。
3. **核验和保存。** 看到“已实际解密核验”后，将显示的整份五文件备份目录复制到另一台设备。打开原站，确认上一次登记的账目和收支合计。

**把旧站的备份恢复到新站（Mac）。** 先建一个独立空站，暂时不要注册账号。打开**新站**的 `data/本站维护说明.txt`，复制“恢复到本站”里的整段命令。在 Mac 终端进入同版本站主工具目录，粘贴并运行命令。命令已填好新站的地址、项目名和目录。按提示选择**旧站的备份**和**创建这份备份时对应的原钥匙**，确认目标网址是新站后再开始恢复。[查看完整恢复步骤](docs/从备份恢复.md)

**以后在用旧备份恢复的新站记账。** 这个站首次备份前，可以选“登记旧钥匙”沿用恢复时用的钥匙，也可以选“生成新钥匙并登记”。已经登记过就直接运行这个站的“手动备份”。请保管好每份备份对应的 `.agekey` 原文件。[用旧备份恢复的新站怎样备份](docs/从备份恢复.md#用旧备份恢复的新站今后怎样备份)

群晖手动备份支持 Container Manager 24.0.2-1543 和 24.0.2-1606，任务启动时会校验套件文件。若显示 `CM_vendor_file_set_unreviewed`，此项检查会在停站前结束任务。请反馈套件中心显示的 Container Manager 版本号和任务计划中的运行结果。

## 证书到期与续签

新建站点或续签时，网站 HTTPS 证书有效 **365 天**。旧证书继续使用到当前到期日，续签后采用新期限。打开 `data/本站维护说明.txt`，运行“查看证书有效期”可看到网站证书和根证书各自的到期时间。

**群晖只需为每个站设置一次排程。** 按维护说明中的“群晖自动续签网站证书”新建并启用每天运行的任务，例如每天凌晨 03:15。网站证书还剩 30 天或更短时才续签，换证时网页会短暂停用。若已设置 DSM 邮件通知，可在任务中选择仅在脚本异常终止时发送运行详情。需要在群晖上立即换证时，可运行“续签本站 HTTPS 证书”，再从原网址核对新到期时间。[群晖任务计划说明](https://kb.synology.com/zh-cn/DSM/help/DSM/AdminCenter/system_taskscheduler?version=7)

本版新建站点的根证书到公元 **9999 年 12 月 31 日 23:59:59 UTC**。已有站点保留原根证书及原到期时间。换发网站证书会沿用本站根证书，已信任它的设备可继续访问原网址。若工具提示现有根证书有效期不足以签发完整的 365 天网站证书，请在当前网站证书到期前备份并恢复到独立新站，核账并信任新站根证书后切换。早期版本请先按指南升级。[升级与回退](docs/站主升级.md)

站主可查阅[账号找回](docs/站主找回账号.md)和[升级与回退](docs/站主升级.md)。
