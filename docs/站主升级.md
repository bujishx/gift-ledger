# 往来有礼 · 站主升级

**你决定什么时候升级。** 每份发行版 YAML 都指定镜像版本。平时重启网站会继续使用原版本。想升级时，先看目标版本的发行说明，确认它支持你当前的版本和数据库，再选一段可以暂停记账的时间。

## 先留一份可用的备份

1. 暂停新增或修改账目，用原账号记下最后一笔的联系人、金额及当前收支合计。
2. 原版本带有站点维护网页时，在原站点“开始备份”，等核验成功后下载 ZIP。使用旧版本时，Ubuntu 在原站 YAML 所在目录执行 `docker compose run --rm backup`。群晖在「控制面板 → 任务计划」手动运行已经设置好的本站备份任务。
3. 等整站备份与解密校验成功，把下载的 ZIP 或 `backups/artifacts/本次备份编号/` 整个目录复制到另一台设备。确认五个文件齐全，能找到分开保管的对应原钥匙。另存原版本号、原 YAML、同版站主工具，以及可重新取得的原镜像摘要；离线部署请同时保留原镜像包。

## 在原站应用新版 YAML

取目标发行版的 `docker-compose.yml`，沿用原站的项目名、局域网 IP、HTTPS 端口和数据目录设置。若原来使用 `.env` 指定这些值，继续在原目录使用它。站点文件、数据库和证书都留在原处。

| 环境 | 操作 |
| --- | --- |
| **Ubuntu** | 用准备好的新版 YAML 替换原文件，在原目录依次执行 `docker compose --profile maintenance pull` 和 `docker compose up -d`。离线测试包先导入配套镜像，再执行 `docker compose up -d`。 |
| **群晖** | 打开 Container Manager 的「项目」，选择**原项目**。在「YAML 配置」里编辑并保存新版内容，再对这个项目执行「构建」。使用离线测试包时，先在「映像」中导入该版配套镜像。 |

**成功标志**是原网址能打开，原账号和密码能登录，最后一笔及收支合计一致。再运行一次整站备份，看到新编号和校验成功，即可恢复日常记账。

本次群晖测试中，更新过的项目点「重新启动」曾报 1202。遇到此提示，或 `initialize` 退出码为 1，请选原项目，用当前 YAML 执行「构建」。等 `db`、`api`、`web` 健康，`prepare`、`initialize` 退出码均为 0，再登录核账。

首次升级到带有网页维护的版本，在服务器管理员终端运行新说明中“启用本站网页维护（每站一次）”的命令。群晖按该节设置本站的开机任务。从 v1.7.0 或 v1.8.0 升级到 v1.8.1 的站，先等本站备份、恢复、钥匙登记、换钥和证书任务结束。用新生成的说明重新运行同一节的安装命令，升级原站绑定的宿主维护服务。按命令输出核对站点实例。群晖已有的开机任务按新说明核对脚本，Ubuntu 用安装结果核对本站服务。打开“维护操作 → 本站备份钥匙”，核对当前公钥和首次备份核验结果。历史登记显示“登记时文件名：未记录”时，可点“核对本地钥匙”确认手里的文件。

升级后，在 `data/` 打开自动生成、带“项目名-实例前8位-”前缀的“本站维护说明.txt”（旧版使用固定文件名），核对网址和项目名。若项目文件夹显示“查看本站目录”，在宿主机运行该节整段命令，再重新打开说明。已有 DSM 手动备份任务应使用新版说明中整段“手动备份”脚本。

若维护说明里有“查看证书有效期”，可用它核对当前到期时间。原先签发的 90 天网站证书到下次续签时换为 365 天。升级会保留原根证书和原到期时间。新建站点的根证书到公元 9999 年 12 月 31 日 23:59:59 UTC。要在群晖启用自动续签，按“群晖自动续签网站证书”设置本站的每日任务，和手动备份分开。若已有本站的自动续签任务，更新其脚本并核对排程即可。早期自签证书站点请按维护说明里的“证书维护”操作。

### 群晖提示容器登记编号过期

如果换钥提示 `container_manager_identity_outdated`，服务器已在启用新钥匙前停止。保管好原钥匙、本次已保存的新钥匙及确认码。站主可以先继续使用原账本，选一段维护时间，请服务器管理员核对。下列命令只显示本站 Web 和 API 容器编号的核对结果。在群晖管理员终端进入 `sudo -i`，从 Container Manager 的「项目」复制实际项目名填入提示。

```sh
printf '本站项目名：'; IFS= read -r gl_project
/usr/bin/python3 -I - "$gl_project" <<'PYCHECK'
import json, re, subprocess, sys
from pathlib import Path
project = sys.argv[1]
if not re.fullmatch(r"[a-z0-9][a-z0-9_-]*", project):
    sys.exit("项目名无效")
docker = "/var/packages/ContainerManager/target/usr/bin/docker"
for role in ("web", "api"):
    name = f"{project}-{role}-1"
    found = subprocess.run([docker, "inspect", "--type", "container", "--format",
        '{{.Id}} {{index .Config.Labels "com.docker.compose.project"}} {{index .Config.Labels "com.docker.compose.service"}}',
        name], capture_output=True, text=True)
    fields = found.stdout.strip().split()
    if found.returncode or len(fields) != 3 or fields[1:] != [project,role]:
        print(name, "未核对到本项目容器"); continue
    try:
        data = json.loads((Path("/var/packages/ContainerManager/etc") / (name + ".config")).read_bytes())
        print(name, "一致" if data.get("id") == fields[0] else "编号过期")
    except (OSError, ValueError):
        print(name, "未读到群晖登记")
PYCHECK
```

先确认站外已保存一份可用备份和对应原钥匙，记下最后一笔账。对于显示“编号过期”的单个 Web 或 API 容器，管理员可在 Container Manager 的「容器」页核对**完整容器名**，停止它，确认已停止后删除这一个容器，再到「项目」对同一个原项目执行「构建」。保留项目、数据库、卷、镜像、文件夹及其他容器。每次处理一个容器，随后重跑上面的只读检查。

本次群晖实测中，旧登记会导致停止操作报告 `1301`；项目构建也可能报告 `1202`，但已创建替换容器。遇到这种情况，先在原项目看实际容器和状态。若替换容器已出现、只读检查显示“未读到群晖登记”，在「容器」页对这个**新建的同名容器**单独停止、启动，再核对一次。若超过这两种情况、容器身份不清楚或服务未恢复，请停在当前步骤并保留运行结果。两个编号均一致且原账号核账正常后，可用原保存确认码继续本次换钥。

## 升级后遇到问题

1. 暂停当前站点的写入，保留原项目及其文件、升级前的 YAML 和已经核验的离机备份。记下升级后新增或修改的记录，用来核对备份时间之后的差额。
2. 使用**升级前的版本**在独立空目录建站，换项目名和空闲端口，使用该版本的原镜像及原版 YAML。除建站所需的项目名、IP、端口和独立目录外，保留版本设置。先让目标成为尚未注册账号的空站。
3. 在这个空站按它所用版本的恢复指南，用**升级前的备份和对应原钥匙**恢复。回退到 v1.6.0 时，在目标站的维护说明找“恢复到本站”，使用 v1.6.0 的 Mac 或 Windows 站主工具。如果当时的说明还没有填入目录，先在目标服务器运行“查看本站目录”，再打开更新后的说明。
4. 核对新目标站根指纹并信任它。用原账号登录，检查最后一笔和收支合计与升级前的记录一致。逐笔处理备份后发生的变化，再切换日常使用的网址。这座用旧备份恢复的新站首次备份前还需登记日常备份钥匙。

只有对应版本的发行说明明确支持原地回退时，才在同一项目替换回原 YAML 并按原版本启动。[从备份恢复](从备份恢复.md)

从带站点前缀的版本原地回退到 v1.7.0 时，须先按当前版“本站维护说明”中还原旧版文件名的步骤，用当前镜像运行 `prepare rollback-public-files`。待命令成功，核对旧版需要的“网站地址.txt”“本站根证书.cer”“本站维护说明.txt”，再替换原 YAML。旧版启动时会拒绝无法识别的新增文件和目录。若有自己的文件放在站主指南目录，请先移到站外保存。这一步只转换公开站点资料，数据库版本兼容性和备份回退仍按上面的条件核对。

若发行说明明确支持向 v1.5.0 原地回退，先停用本站的 DSM 自动续签任务，将 `data/本站维护说明.txt` 移到项目的 `data` 目录以外保存。v1.5.0 的安装检查仅接受当时支持的公开文件名。回退后按该版原来的任务脚本操作。
